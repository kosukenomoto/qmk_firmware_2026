# s202409 / split34 レビュー（2026-09-30）

照合対象は `~/proj/keyboard_pcb/split34/split34.kicad_sch` と `split34.kicad_pcb`。
ファームウェアは共通設定と現行 `keymaps/20260930/keymap.c` を修正した。
基板ファイルは変更していない。`default` はビルド互換性のみ修正、過去の日付のキーマップは未修正。

## 修正した問題

| 問題 | 影響・修正 |
| --- | --- |
| direct pinの親指行が3要素のみ | 5列のC配列では残り2要素が0になり、`NO_PIN`として扱われず、意図しないGPIOレジスタを読み書きする。左右とも`null`を2個追加し、生成コードを`NO_PIN`にした。 |
| 右Bootmagicの行指定がない | 右側USB接続時も左側の行0を判定していた。右の行4・列0（SW20）を指定した。 |
| CM_QFN / CM_NUMの状態がキーコード単位で共有 | CM_QFNは左右に2個、CM_NUMは右に2個ある。片方を離すともう片方を保持中でもレイヤーを解除し、時刻の上書きや意図しないSpace・半角全角も起きうる。物理位置ごとの時刻・タップ候補と保持数で管理する。 |
| Alt+Tab終了時の`layer_clear()` | 数字レイヤーキーの解放でもAlt+Tabを終了し、他の保持中レイヤーも消していた。最後のQFN解放でAlt+Tabを終了し、対象レイヤーだけを解除する。 |
| 記号キーが物理Shiftを`unregister_code()` | 記号を離すと押したままのShiftを消していた。weak modifierを使い、記号キー同時押しは保持数で管理する。 |
| 半角全角・Alt+Ctrlマクロが物理修飾キーを書き換え | 物理Alt/Ctrl/Shiftを解除する可能性があった。マクロはweak modifierを使い、終了時に元の状態に戻す。Alt+Ctrlにはホスト向けレポートと既存と同じ60 msの待ちを入れる。 |
| weak modifierはQMKが新しいキー押下時に消去 | 修正後も記号やAlt+Tabを保持できるよう、前処理・処理・後処理で必要なweak modifierを復元する。Flow Tapのホットキー判定にもweak modifierを含める。 |
| カーソル4回マクロが処理継続 | カスタムキー処理後は`false`を返し、QMKの後続キー処理へ渡さない。 |
| レイアウト座標が基板位置と異なり、親指キーが重複 | PCBの19.05 mmピッチと段差に合わせて表示座標を直した。キーコードとマトリクス位置の対応は維持。 |
| `default`の`KC_BTN1`が現行QMKに存在しない | `MS_BTN1`に更新。 |

## 一致を確認した配線

回路図のKiCad XML netlistを出力し、PCBパッドのnet名・MCUパッド番号と`keyboard.json`を照合した。
全36スイッチで一致。SW19とSW38はリセットスイッチであり、キー入力には含めない。

| 行 | 左U1：SW1–18 | 右U2：SW20–37 |
| --- | --- | --- |
| 上段 | B1, B7, D3, D7, F1 | B4, F4, B0, B1, B7 |
| 中段 | B0, B3, D5, B4, F4 | D7, C7, E6, B3, D3 |
| 下段 | E6, B2, D4, B5, F0 | D6, B6, F0, B2, D5 |
| 親指 | D6, B6, C7 | D4, B5, F1 |

全スイッチはGPIOと各側GNDの間につながる。QMKのdirect pin方式（入力プルアップ、Lowで押下）と一致する。
左右通信は双方PD2 → TRRSのB、GNDはC、電源はD。ピン競合はない。
PF4はJTAGと兼用だが、このQMKの`platforms/avr/platform.c`は起動時にJTAGを無効化する。
左右でピン配置が違うため、EEPROMの左右設定が必須。USBの接続側だけでは物理的な左右を特定できない。
`SPLIT_USB_DETECT`は、TRRSで相手のVBUSにも電源が来る構成でUSB接続側を選ぶために必要。
左の音声回路はPC6、右PC6は未接続。今回の追加依頼で`AUDIO_ENABLE = yes`とし、Timer3によるPC6のPWM音声出力を有効化した。
PC6はキー入力にも左右通信にも使われていない。音楽モードは無効のまま。
起動時に2,000 Hz → 1,000 Hzを各約100 ms再生する（[再現資料](https://bakutek.net/elec/PIC/PiPo4/PiPo4.html)）。
QMK標準の遅延起動音タスクはUSBマスターでしか呼ばれないため、`s202409.c`でスレーブにも呼び出す。
これにより右USB接続時も左スピーカーが鳴る。右単独では音声回路がないため無音。
実機で音が小さいとの報告を受け、PWMデューティ比を標準50%から17%へ変更した。
基板指定のPKMCS0909E4000-R1は4 kHz向け。2 kHzと1 kHzの双方に4 kHzの倍音成分を加える狙いで、周期・音長・ピン割り当ては同じ。
[村田製作所のFAQ](https://www.murata.com/en-us/support/faqs/sound/sounder/char/sch0006)は2 kHz・25%での音圧改善例を示すが、別の型番による測定なので、この基板での改善幅は保証できない。
17%は第2・第4倍音の双方を強めるために選んだ値で、メーカー指定値ではない。実機での音色・音量確認が必要。

## 基板側で残る事項

KiCad 9.0.8のDRC（`--schematic-parity`）は未配線0件、通常指摘531件、回路図との対応指摘3件だった。
531件は危険な回路が531か所あるという意味ではなく、穴・製造用フットプリント・シルク・ライブラリ環境の指摘を含む。

* USB1のシールドGNDパッド13（B.Cu）、USB2のパッド13（F.Cu）は、サーマル接続が要求2本に対して1本。断線との判定ではないが、実装品質と接続の余裕を確認する必要がある。
* 穴同士の距離199件、穴の同位置重複56件、穴径36件、クリアランス16件、マスク開口32件など。確認したクリアランス16件はすべて同じ位置に重複する`REF**`のnetなしPTHパッド。電源・信号間短絡の証拠ではなく、製造データの重複として確認する。
* 回路図との対応3件はmouse-biteフットプリントの重複1件・追加2件。MCUやスイッチの配線不一致は報告されていない。
* TRRSのDで左右のVCCを直結し、各VCCはそれぞれUSB VBUSにも直結している。両USBを同時接続すると、電源が相互につながり、双方が通信マスターにもなりうる。逆流防止回路はnetlist上にない。TRRS接続中のUSBは片側だけにする。これはファームウェアでは電気的に遮断できない。
* TRRSは挿抜時の接点順序で電源と他の接点が一時的に接触するおそれがある。電源を外してから挿抜する。
* 外部16 MHz水晶と実機のクロックfuse、DFUブートローダー、実装部品は設計ファイルだけでは確認できない。
